# Вход через Google: что нужно настроить

Вход реализован на официальном SDK
[GoogleSignIn-iOS](https://github.com/google/GoogleSignIn-iOS) (подключён
как Swift-пакет в `project.yml`). Client ID в репозитории **не хранится** —
это идентификатор конкретного проекта в Google Cloud, а не константа
приложения. Пока он не задан, экран знакомства прямо пишет, что вход не
настроен, и даёт пройти дальше — иначе приложение нельзя было бы открыть
вообще.

## Шаги

1. Google Cloud Console → создать проект (или взять существующий).
2. APIs & Services → Credentials → **Create credentials → OAuth client ID**
   → тип **iOS**.
3. Bundle ID указать `com.lumi.app` — ровно как `PRODUCT_BUNDLE_IDENTIFIER`
   в `project.yml`.
4. Скопировать два значения: **Client ID** и **Reversed client ID** (это тот
   же идентификатор задом наперёд, начинается с `com.googleusercontent.apps.`).
5. Подставить их в `project.yml`, в блок `settings.base`:

```yaml
    GOOGLE_CLIENT_ID: "1234567890-abcdef.apps.googleusercontent.com"
    GOOGLE_REVERSED_CLIENT_ID: "com.googleusercontent.apps.1234567890-abcdef"
```

6. `xcodegen generate` — значения попадут в `Info.plist`: `GIDClientID` и
   схема возврата в `CFBundleURLTypes`.

Секрета в этих двух строках нет (iOS-клиенты OAuth публичные, client secret
для них не выдаётся), но проект всё равно чужой, поэтому в репозиторий их
никто не коммитит по умолчанию — решает владелец.

## Что вход сейчас делает и чего не делает

Сервера у приложения нет. Из профиля берётся **только имя**, чтобы
подставить его в следующий шаг знакомства; токены никуда не отправляются и
не сохраняются. Настоящие аккаунты — синхронизация прогресса между
устройствами, восстановление после переустановки — появятся только вместе с
бэкендом (Stage 5, `Lumi_Project_Handover.docx`).

## Открытый вопрос к релизу

Раньше на этом экране был Sign in with Apple, и его сняли по прямой просьбе
владельца продукта. Правило App Store (Guidelines 4.8, «Login Services»)
требует, чтобы приложение со сторонним входом предлагало и равноценный
вариант с приватностью — Sign in with Apple ему удовлетворяет. То есть к
публикации Apple-вход, скорее всего, придётся вернуть **вторым** вариантом
рядом с Google. Код для него лежит в истории git (коммит с заменой), так
что возврат — это не переписывание с нуля.

Побочный эффект замены, уже полезный: энтайтлмент
`com.apple.developer.applesignin` выдаётся только платному аккаунту
разработчика. Без него проект собирается и запускается на бесплатной личной
команде.
